# Bioconductor Classes and Methods Working Group

- Description: Discussions arounnd Bioconductor 'official' classes and
  methods and how to articulate their benefits to increase their usage
  across the ecosystem, in particular in new contributions. Contemplation of how
  to integrate S7 framework.
  
- Leads: Laurent Gatto, Michael Lawrence, Lori Shepherd
- Current Members: Vince Carey, Laurent Gatto, Michael Lawrence, Marcel Ramos,
  Lluis Revilla, Dario Righelli, Lori Shepherd, Malte Thodberg, Tim Triche

- Slack: #biocclasses

The BiocClasses and Methods Working Group tackles the following
questions and issues:

- What are [the 'official'
  classes](https://contributions.bioconductor.org/important-bioconductor-package-development-features.html#commonclass)?

- What is the procedure to establish a new 'official' class?

- When should a new package be formed vs adding new methods or extensions to an
  existing class/package?  How to encourage PR and they are as equally of value
  than a distinct package?

- To what extent should these be enforced during package review?

> In general, a package will not be accepted if it does not show
> interoperability with the current Bioconductor ecosystem.

- How do we better encourage the use of classes?

- How will S7 framework integrate into the Bioconductor ecosystem.

- Increase documentation for why classes are valuable, how to use popular
  classes, how to extend a class, intro to S7, ... 

To participate, feel free to open/reply to issues and join the #biocclasses slack channel.
